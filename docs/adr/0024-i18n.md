# Localisation with i18next: English and French

**Status:** accepted (2026-11-01)

All user-visible text comes from `src/shared/i18n/en.json` and `fr.json`. Both processes use them: the renderer through `react-i18next` (`src/renderer/src/i18n.ts`), and the main process through its own i18next instance for the Windows dialogs and its error messages (`src/main/index.ts`). `src/shared/i18n/i18next.d.ts` types the keys from `en.json`, so a wrong key or a missing variable is a type error.

- **Language choice.** The default is the system locale (`app.getLocale()`: French for any `fr-*`, else English). The EN | FR switch in the top bar saves the choice in `settings.json`; IPC `i18n:get` / `i18n:set` keep both processes in line. The renderer applies the language before its first render.
- **Vocabulary.** French texts use the words of the French game UI, so the app and the game say the same thing: Livrée, Carte de la région, Carbone, Autocollants, Poursuivre. Class names (Hypercar, LMP2, LMGT3 …), car names and template layer names are not translated. The glossary lists the French terms.
- **Language-neutral code.** Shared code returns codes, not sentences: `parseProject` returns `ProjectError` codes, custom schema messages are `validation.*` keys, the worker sends stage codes, `readProjectFile` returns `tooLarge` sizes. The UI translates them. zod translates its own messages with its locale (`setValidationLanguage`).
- **Formats.** Numbers use `Intl.NumberFormat` in the UI language ("3.7 s" / "3,7 s", "28 MB" / "28 Mo"). French texts use a non-breaking space before `:`, `?` and `%`.

## Consequences

- Add every new text to both files. A unit test (`src/shared/i18n/i18n.test.ts`) fails when the key sets or the variables of a text differ, or when a text is empty.
- French is often 15–30 % longer: check new UI in both languages (the footer of the editor had to change for "Carte de la région").
- The Bebas Neue font has capitals only: the top bar shows the screen title in it, and the file name next to it in the body font.
- Not done yet: a lint rule against hard-coded strings (needs ESLint).
